# Phase D3 — Paiement sandbox signé : plan d'implémentation

> **Pour les agents :** exécution task par task avec cases à cocher (`- [ ]`). TDD : test d'abord,
> implémentation, test vert, commit. 1 commit par task.

**Goal :** encaisser la commande via `MockPaymentGateway` signé (HMAC) — initiation USSD simulée,
webhook idempotent, machine à états `Payment`, réconciliation par cron, page de paiement FR.

**Architecture :** nouvelle app `apps/payments` (modèle `PaymentEvent`, gateway HMAC, machine à
états `apply_status`, endpoint webhook AllowAny signé, initiateur, simulateur de scénarios, cron
`poll_pending_payments`). Les modèles `Payment`/`Order` restent dans `commerce` ; seul
`apply_status` (dans `payments.services`) écrit `payments.status` pour les transitions
pilotées par le fournisseur (règle payments.md §2.1.4). Locks : **toujours `order` avant
`payment`** (anti-deadlock avec `expire_stock_reservations`/`cancel_order`).

**Tech Stack :** Django 6.1 + DRF, `hmac`/`hashlib` stdlib, Next 16 client components.

**Spec :** `docs/payments.md` (§1.1, §2, §2.1, §2.2, §2.3, §5) + `docs/requirements.md` EX-4.
Décisions utilisateur (2026-10-28) : (1) page dédiée `/commandes/{ref}/paiement`, redirection
immédiate depuis checkout ; (2) `FAILED` → libération stock + commande ANNULÉE ; (3) cron
polling inclus en D3.

## Global Constraints

- Erreurs enveloppe `{"error":{"code","message","details"}}` ; codes : `validation_error` 400,
  `not_found` 404, `conflict` 409, `invalid_signature` 403, `unauthenticated` 401, `rate_limited` 429.
- XAF entiers ; montant webhook **strictement égal** à `order.grand_total_xaf` sinon rejet 409 + `logger.warning`.
- Frontend : appels API **sans slash final**, réponses plates, UI FR, cookies HttpOnly+CSRF via `apiFetch`.
- Secrets uniquement en env : `PAYMENT_PROVIDER` (défaut `mock`), `PAYMENT_WEBHOOK_SECRET`
  (défaut `artflow-dev-webhook-secret`) — jamais en base ni en git.
- Header signature : `X-ArtFlow-Signature: sha256=<hex HMAC-SHA256(body, secret)>`, vérifié avec
  `hmac.compare_digest` sur le corps **brut** ; rejet de tout corps altéré.
- Seule source de vérité = webhook/cron ; **jamais** de confirmation navigateur (payments.md §2.1.1).
- Rejeu `event_id` → **HTTP 200 no-op** ; transition illégale / montant erroné → **409 + log**.
- Nouvelle migration ⇒ `uv run python manage.py migrate` sur la BDD dev avant smoke.
- Suites backend lentes : `timeout 360000 uv run pytest -q -p no:cacheprovider`, s'appuyer sur l'exit code.

## Review Focus

1. **Montant webhook ≠ total commande** → rejet 409, aucun état ni `PaymentEvent` écrit — test
   `test_amount_mismatch_rejected` (Task 2).
2. **Événement contradictoire après état terminal** (ex. `FAILED` après `SUCCEEDED`) → 409, état
   inchangé ; **rejeu du même `event_id`** → 200 no-op, `mark_paid` exécuté **une seule fois** —
   tests `test_late_conflicting_event_rejected`, `test_duplicate_event_id_noop` (Task 2/3).
3. **Corps signé modifié après calcul de la signature** → 403 `invalid_signature`, commande
   inchangée — test `test_webhook_tampered_body_rejected` (Task 3).
4. **`initiate` concurrent (double clic)** → un seul passage `PENDING`, aucun 500 — test
   transaction+threads+barrier `test_initiate_concurrent_single_pending` (Task 3).
5. **`SUCCESSFUL` après annulation/expiration** (webhook tardif, argent encaissé) → commande
   `PAID`, stock **jamais négatif** (clamp 0 + `logger.warning` finance) — test
   `test_late_success_after_cancel_accepts_payment` (Task 2).
6. **Polling borné** : `poll_count ≥ 20` → plus d'interrogation fournisseur — test
   `test_poll_stops_after_max_attempts` (Task 4).

### Task 2 : Machine à états `apply_status` + side effects

**Files:**
- Modify : `backend/apps/core/exceptions.py` (classe `InvalidSignature(APIException)` :
  `status_code=403`, `default_detail="Signature de webhook invalide."`, `artflow_code="invalid_signature"`)
- Modify : `backend/apps/commerce/services.py` : `mark_paid(order, *, late=False)` ;

- Create : `backend/apps/payments/services.py`
- Test : `backend/apps/payments/tests/test_services_payment_state.py`, `conftest.py` local si besoin

**Interfaces:**
- `TRANSITIONS` : `CREATED→{PENDING, CANCELLED}`, `PENDING→{SUCCEEDED, FAILED, EXPIRED, CANCELLED}`,
  terminaux → `{}` ; **re-reçu du même état** = no-op (pas une illégalité).
- `payments.services.apply_status(payment: Payment, new_status: str, *, failure_reason: str = "") -> Payment`
  — **appelé uniquement sous verrou tenu par l'appelant** (locks order→payment), valide la
  transition (sinon `Conflict`), écrit le statut, puis side effects :
  `SUCCEEDED` → `commerce.mark_paid(order, late=order.status == CANCELLED)` ;
  `FAILED`/`EXPIRED` → `commerce.release_order_after_payment_failure(order)` (no-op si commande
  non `PENDING_PAYMENT`) ; `CANCELLED` → aucun (l'appelant gère la commande, cf. `cancel_order` D2).
- `payments.services.ingest_event(*, event_id, external_reference, status, amount_xaf, payload,
  source="WEBHOOK") -> dict` — atomique, lock order→payment ; `Http404` si réf inconnue ;
  `PaymentEvent` existant → `{"duplicate": True, ...}` sans rien écrire ; montant ≠
  `payment.amount_xaf` → `Conflict` + `logger.warning("montant")` ; mappe
  `provider_to_internal` (le payload mock envoie `SUCCESSFUL`) ; transition illégale → `Conflict` +
  `logger.warning` ; sinon `apply_status` + crée `PaymentEvent` ; retour
  `{"event_id", "payment_status", "order_status", "duplicate": False}`.
- `mark_paid(order, *, late=False)` : sans changement si `late=False` (garde stock négatif
  `APIException` existante) ; `late=True` accepte commande `CANCELLED`, et si stock insuffisant →
  `stock_quantity = 0` (jamais négatif) + `logger.warning("finance: stock insuffisant…")`.
- `release_order_after_payment_failure(order)` : lock order, si `PENDING_PAYMENT` → réservations
  `ACTIVE→RELEASED released_at=now`, commande `CANCELLED`+`cancelled_at` (le verrou payment est
  déjà tenu par l'appelant, le payment reste en `FAILED`).
